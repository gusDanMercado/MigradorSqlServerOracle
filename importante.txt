ESTAS EJECUCIONES SE DEBEN REALIZAR UNA UNICA VEZ YA QUE SOLO FUNCIONAN PARA LA PRIMERA MIGRACION
Y SI SE EJECUTAN POR SEGUNDA VEZ PUEDEN TENER PROBLEMAS POR LAS CLAVES FORANEAS.


AL CREAR LOS ARCHIVOS DE CADA UNA DE LAS MIGRACIONES EJECUTAR
dotnet build


ORDEN RECOMENDADO PARA EJECUTAR LAS MIGRACIONES POR PRIMERAS (EJECUTAR UNA UNICA VEZ)

dotnet run -- plancuentas

dotnet run -- agruprove
dotnet run -- proveedores

dotnet run -- rubroporcuenta

dotnet run -- subgruposproduc
dotnet run -- productos
dotnet run -- existencias

FALTARIAN: (QUE YA ESTAN MIGRADOS CON INSERTS NORMALES)
--> LOS INSERT NORMALES SON PARA LOS QUE TENIAN UNA O DOS FILAS O PARA LOS QUE SON TABLAS NUEVAS

#### MODULOCENTRAL
UNIDADESOPERATIVAS --> MANTENIMIENTO.M_CENTROCOSTO (atributos DISTRITO CODDISTRITO serian mi unidad operativa) --> GESP   ///   -- inner join de auxiliares y compras_compro_ccosto (COSAYSA)  --> TRAIGO DEL GESP
dotnet run -- localidades --> TENEMOS DOS TABLAS DE LOCALIDAD --> UNA EN AMERICA(SE LLAMA LOCALIDADES) Y OTRA EN EL GESP(GESTION.LOCALIDADES)  --> SE QUEDAMOS CON LA DEL GESP
UNIDADESMEDIDA     --> TABLA NUEVA 
DISTRITOSCOMPRA    --> ES LA MISMA TABLA QUE HAY QUE UNIFICAR --> ES MAS FACIL ACTUALIZARLA EN INVENTARIO (SE TENEMOS QUE QUEDAR CON ESTA TABLA)  (SERIA UNIDADESOPERATIVAS)
